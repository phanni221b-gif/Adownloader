# Adownloader architecture

## Preserved engine contract

The launcher is `MainActivity`; browser rendering remains GeckoView 159 with the built-in native-messaging WebExtension. Android System WebView is not an execution path. The media downloader is independent of Activity and Gecko session lifetimes. HLS selection remains resolution, frame rate, then bitrate; DASH keeps the highest supported original video and audio. Post-processing copies samples through MediaMuxer and never instantiates an encoder. DRM is unsupported.

## Durable downloads (v0.6 phase A)

`DownloadJobs` coordinates one transfer worker, a separate serialized command executor, and an application-owned `DownloadJobStore`. UI callbacks run on the main thread; network, hashing, encryption and transfer execution run off it. Android 34+ uses a user-initiated data-transfer JobService with its required notification and network constraint. Android 30–33 uses a dataSync foreground service. A scheduling restriction produces a recoverable paused state rather than a fake active transfer. User resume originates from a visible Activity. Neither a process nor an operating-system job is assumed immortal.

SQLite schema version 1 has `jobs`, `parts`, `contexts` and `flags` tables. `jobs` stores the job identifier, opaque identity, media category, safe display name and source host, state, created/updated times, actual committed bytes, nullable total bytes, segment progress, error category, queue priority, MediaStore pending/completed URI and worker PID/process epoch. Sensitive request context is a single authenticated ciphertext, not URL or cookie columns. `parts` keys each committed segment by job/track/part with its byte count and SHA-256. `flags` records one-time migration of v0.5 history. WAL plus FULL synchronization makes committed checkpoints durable. Unknown totals stay unknown; percentages are only derived from known byte or segment totals.

The context envelope uses a non-exportable Android Keystore AES-256 key, fresh 96-bit IV, AES-GCM and job-ID additional authenticated data. Versioned bounded GZIP data is encrypted before SQLite receives it; decompression and ciphertext sizes are bounded. The request URL, minimal request headers, manifest plan, range validators and direct-file hashes stay inside this envelope. Large ciphertexts use ordered 512 KiB `contexts` rows, atomically replaced in a SQLite transaction. The complete envelope is authenticated after bounded reassembly, so missing, reordered or substituted chunks cannot silently decrypt. This avoids CursorWindow limits with thousands of long signed segment URLs. There is no plaintext recovery fallback. Cookies are supplied for the actual media request only; the download queue does not export a browser cookie jar or collect Authorization headers. Failed decryption requires safe source refresh. Release signing uses a separate, pre-existing RSA key and is unrelated to this per-installation AES key.

An atomic claim advances QUEUED to PREPARING. Guarded transitions lead to DOWNLOADING, FINALIZING and COMPLETED. Pause, cancellation and resume are real worker controls, not label changes. A resume requested while the previous worker is closing is deferred and applied on the serialized command executor. Queue priority changes the next atomic claim. A fresh process reconciles the persisted worker PID plus a random process epoch, so PID reuse does not revive a dead worker. Previous active work becomes PAUSED only after its committed data has been checked. Invalid checkpoints fail safely. A published MediaStore row can be adopted only after media inspection.

Direct-file checkpoints commit after file synchronization and include prefix length, SHA-256, expected total, strong ETag or Last-Modified and completion flag. Uncommitted tail bytes are truncated. Resume verifies the saved prefix, sends Range and If-Range, and validates status, Content-Range, length and validators before appending. A full 200 response restarts at zero. Malformed or changed partial responses cannot be appended. HLS/DASH plans and selected representations are saved before fetching segments; each segment is synchronized and renamed before its size/hash is committed. A missing or changed committed segment is an error rather than permission to mix versions. Reopening uses the same saved maximum-quality plan.

MediaStore output remains pending during copying and validation. Completion follows duration, track and seek checks. Cancellation stops active I/O, removes workspace and pending media, and clears request secrets. Failed cleanup retains the required URI and an explicit cleanup-pending marker for a later retry. Completed source workspaces are also cleaned on startup. Clearing terminal history does not delete the user's published media.

Phase A initially used private transfer files. Phase D replaces that path with direct pending-descriptor output and virtual segment sources, as documented below.

## Verification

Host tests exercise exact Range resume, changed/ignored range restart, corrupt prefix rejection and malformed partial responses. Android tests check authenticated encryption, job-bound additional data, absence of plaintext secrets in DB/WAL, old-process recovery, cancellation cleanup, queue ordering, process-epoch ownership and bounded large plans. Segment tests reuse committed HLS/DASH pieces. An external adb harness stops the actual application process between checkpoint creation and recovery, verifies final direct-file SHA-256/Range requests, and checks that committed HLS/DASH parts are not fetched twice. The harness separately exercises pause/resume, immediate resume, cancellation and retry after a server failure. Passing results must be recorded per tested commit; a test's presence alone is not a pass.

References: [Android user-initiated transfers](https://developer.android.com/develop/background-work/background-tasks/uidt), [foreground service time limits](https://developer.android.com/develop/background-work/services/fgs/timeout), [JobService](https://developer.android.com/reference/android/app/job/JobService), [MediaMuxer](https://developer.android.com/reference/android/media/MediaMuxer).

Physical Galaxy Fold8 validation requires the actual device. Emulator evidence must not be described as a physical Fold8 test.

## Authenticated detection and refresh (v0.6 phase B)

The built-in extension now keeps only Cookie, Referer, Origin and User-Agent temporarily in a bounded request-ID map. It does not transmit request context before a successful media response is recognized. Completion and error remove that context immediately; a time/entry bound handles abandoned requests. Authorization and the browser cookie jar are not collected. DOM/performance observations remain a fallback. Confirmed MIME takes precedence over misleading extensions and guessed element types. Late DOM/performance observations cannot replace a newer authenticated network candidate. Native delegates are released when their owner closes.

`MediaIdentity` separates exact type/full-URL dedupe from conservative logical grouping by MIME-derived media category, page origin, media origin/path and retained semantic query parameters. Known volatile authentication/cache parameters are considered only for identifiable resources; ambiguous generic token-only endpoints remain distinct. Parameter order is retained so repeated semantic keys are not reordered. Actual download URLs are never canonicalized or stripped: the newest confirmed full URL and its own request headers remain the source. The UI list is bounded to 200 groups and download clicks resolve the latest member again.

`HttpSource.document` reads and validates one response instead of opening a second GET. `MediaProbeService` shares an in-flight/complete original-quality plan between preview and download, scoped by exact URL plus request-header digest. It uses a short 60-second TTL, known signed expiry, response validators for revalidation when an expired previous response remains available, and bounded entry/byte counts. Sensitive manifests and headers stay in memory; durable selected plans stay encrypted. Preview work has an Activity-independent owner; closing a preview cannot interrupt a downloader sharing that response. Only the first visible preview batch is prefetched. The existing HLS and DASH maximum-original selectors remain responsible for selection; their actual representation metadata is carried with the plan.

Final filenames prefer a usable Content-Disposition filename, then page title, URL basename, media title and a dated fallback. RFC 5987 UTF-8 is supported; traversal paths, control characters, invalid filename characters, excessive byte lengths and URL-like titles are rejected or sanitized. The extension comes from inspected output. MediaStore creates unique names and the actual provider-assigned name is recorded; Android integration verifies `(1)` collisions.

401/403 produces NEEDS_REFRESH. Revisiting the original page can offer an explicit new-address link for the same identity. Direct files retain their checkpoint and validate actual Range/ETag/length before appending; a changed full response restarts at zero. HLS/DASH reuse additionally requires compatible selected tracks, codec/language/quality metadata, complete part order, byte ranges, sequence, IV and key/media resource paths. Authentication query rotation is compared only inside that already matched identity. A lower original quality is not accepted automatically. Incompatible plans with insufficient quality evidence remain paused for source refresh rather than mixing cached pieces or silently reducing quality. Refresh application checks the current durable state again, so cancellation cannot resurrect a job.


## Phase C browser boundaries

NavigationPolicy accepts user-initiated HTTP redirect chains until the location commits or the load stops. A script navigation cannot borrow pending navigation trust. Scheme and effective port are part of the origin comparison; there is no ten-second allowance. New windows and external schemes retain explicit popup controls.

BrowserSessionManager retains at most five GeckoSession objects. Each tab owns its navigation policy, minimal history snapshot and bounded MediaDetector. Background tabs are inactive; tab selection reattaches the existing session. WebExtension 2.3 binds its numeric tab ID through an isolated top-level content-script native message and Gecko MessageSender.session; media response headers still travel only after MIME classification. Pending responses are bounded until this binding arrives. No cookie jar or Authorization collection is added.

BrowserDataStore writes one atomic AES-GCM encrypted file with a separate negative AAD namespace on an application-owned serial I/O executor. The v0.5 plaintext session/last_url preferences migrate once and are removed only after successful encrypted persistence. Session snapshots read public URL/title/history-index accessors: formdata, DOM storage, opaque history state and inline URL credentials are excluded. Bookmarks and the latest 100 history entries are encrypted too.

Desktop mode changes Gecko's documented user-agent and viewport settings on the retained session. Find-in-page uses SessionFinder. Data deletion closes open sessions before StorageController clears host/all data, as required by the frozen Gecko159 source documentation; the resulting blank session cannot immediately repopulate cleared website storage. Bookmark/history deletion affects records only.

API provenance: the immutable org.mozilla.geckoview:geckoview:159.0.20261022150525 sources.jar, particularly GeckoSession, GeckoSessionSettings, SessionFinder, StorageController and WebExtension. The current moving central Javadoc is not treated as the pinned API. Phase C acceptance: workflow 41259025797 (see TESTING.md). The frozen engine also emits an initial synthetic about:blank lifecycle; pending explicit navigation remains URL-bound until its own page-start event rather than being canceled by that initial lifecycle. Active-tab recovery replaces only that session. Long-pressed HTTP(S) links can open in the current tab or a new retained tab; their media still goes through actual response detection.

## Format, storage and fold handling (v0.6 phase D)

Normal direct files now stream into a seekable, unpublished MediaStore Video/Audio descriptor. The encrypted `directMedia` checkpoint binds synchronized byte length and prefix hash to the same pending row. Recovery truncates only uncommitted tails, verifies the prefix and performs the existing Range/If-Range validation. There is no second private copy for normal MP4/WebM downloads. Typed collections are required: the generic Files collection does not permit initial Movies/Music insertion on Android 36.

Segment payloads and AES-128 decryption stream through 128 KiB buffers into synchronized staging files, with fresh decoder state for every retry. `JoinedInput` presents verified segments as one long-addressed virtual source with at most one open segment file. Android MediaExtractor reads that source and MediaMuxer writes directly to the pending MediaStore descriptor; there is no aggregate input file or additional private final file. Segment storage plus final output remain necessary while finalization is being validated. Available capacity is checked for known direct lengths, incoming segments and the estimated mux output. A rare direct-container conversion keeps a hashed, synchronized finalized cache before overwriting its original pending input; its encrypted checkpoint survives interruption. No encoder or FFmpeg binary is shipped.

Pending-row insertion and job association share the store lock. Startup reconciliation also removes unreferenced, app-owned IS_PENDING=1 rows only from Movies/Adownloader and Music/Adownloader. All job pending/completed references are protected, and published rows are never orphan-cleanup targets. Completed records can be cleared without deleting media. Loss of the active OS transfer owner pauses its worker instead of leaving it running without a JobService/foreground owner.

Safe VOD planning retains maximum video resolution, FPS and bitrate priority, selected default/auto audio group, alternate audio language metadata and subtitle rendition metadata. Subtitles are not muxed or downloaded separately. Explicit typed failures distinguish DRM, malformed manifests, unsupported codecs, missing HLS segments, HLS discontinuities, DASH multiple Periods and live input. No tag is silently skipped to manufacture a successful file. HLS discontinuity and multi-Period timestamp/codec continuity are not sufficiently validated by this platform-only pipeline, so they are rejected. Live recording is deliberately unavailable: a rolling playlist requires a separate durable sequence/window ledger and explicit stop/finalization semantics, which this finite VOD plan cannot safely promise. There is no fake record button or unbounded VOD completion claim.

FFmpeg was not added. A maintained ARM64 integration, its licenses, updates and package-size impact would need separate verification before expanding those formats. Native sample-copy remux remains sufficient for the supported VOD paths; lowering quality or reencoding is never a fallback. Platform extractor/container limitations can still cause a clear failure.

Jetpack WindowManager 1.5.1 supplies physical fold bounds, separation, occlusion and posture through its Java callback adapter. Fold changes resize views while retaining the five bounded Gecko sessions. An occluding vertical hinge places the browser in a usable pane, grids distribute complete items on each side, and tabletop layouts keep pages inside one usable region. Toolbars are capped at 720 dp and sheets at 640 dp within a hinge-safe pane. Listeners, sheet watchers, thumbnail requests and Activity-owned executors are released when their owner closes. Thumbnail cache is capped at 8 MiB and recycled row targets are weakly referenced.

Device Diagnostics exports a fixed allowlist of app/Gecko version, Android/model, resolution/density, window/insets/posture and enum-only crash/download failure categories. It does not export browsing state, URLs, hostnames, cookie/header contents, exception text or device serial identifiers. The user chooses whether and where to share the visible report. `geckoVersion` in gradle.properties is the single dependency/BuildConfig/app-info version source. Dependabot proposes weekly Gradle/Actions updates; it never auto-merges them. Gecko upgrades still require the full test and packaging checks.

References: [MediaDataSource](https://developer.android.com/reference/android/media/MediaDataSource), [descriptor MediaMuxer](https://developer.android.com/reference/android/media/MediaMuxer), [Android Os positional I/O](https://developer.android.com/reference/android/system/Os), [WindowManager stable release](https://developer.android.com/jetpack/androidx/releases/window).


## v0.6.1 durable finalization and schema 2

The final pending descriptor is inspected, fsynced, fully hashed and committed to SQLite finalized_media before deleting any segment or private representation input. The original parts hash journal remains. Recovery verifies final length, SHA-256, tracks, duration and seeking, then uses the same pending descriptor without requesting expired sources or remuxing. Failure before that commit preserves all verified inputs. Retry of corrupt storage and incompatible refresh explicitly clear this finalization marker. SQLite foreign-key cleanup removes it with its job.

This shortens the post-finalization overlap and avoids repeat mux on recovery; it does not make platform MediaMuxer resumable halfway through an MP4. Segment plus output peak remains necessary during mux, and final hashing adds I/O. StorageBudget checks remaining estimated input plus output with 10% mux allowance and 8 MiB safety. Known ranges give an input-size sum; bitrate/duration is an estimate; unknown values remain a lower bound. Actual descriptor/segment capacity checks remain active. Typed ENOSPC stays STORAGE_FULL, including wrapped write/fsync failures.

Schema version 2 adds finalized_media and a parts index. Each upgrade step is explicit and runs inside SQLiteOpenHelper's transaction; unknown versions and downgrade fail without resetting data. Migration errors log only version/category, not request data. Existing AES-GCM format/AAD and tables are unchanged. The v0.5 import flag and inserted rows commit together before legacy SharedPreferences payload removal; subsequent opens inspect the flag, not that payload. Records UI observes SQLite, and DownloadHistory is a read-only presentation adapter.

HTTP 401 remains AUTH. HTTP 403 needs a recognized signed URL plus prior accepted transfer or explicit expired timestamp, and no authentication challenge, to become EXPIRED_URL. Both retain NEEDS_REFRESH and original-page reopening. CDN identity and compatible-plan comparison share conservative auth normalization: known AWS fields, scoped CloudFront policy, paired signature/epoch, structured Akamai tokens and JWT signature-only handling. Quality/resource IDs, ACLs, unknown fields, duplicate query keys and JWT payloads are preserved. Actual network URLs/headers are unchanged.
