## 변경 사항

이번 업데이트는 다운로드 로직을 추측으로 고치는 대신, **브라우저 안의 정상 재생과 다운로드 실패가 어디서 갈라지는지**를 휴대폰에서 직접 측정하는 실시간 재생 진단을 추가합니다.

### 재생 진단 (브라우저 메뉴 → 재생 진단 시작)

- PC나 adb 연결 없이 앱 메뉴에서 시작·종료합니다. 진행 중에는 화면 하단에 "종료" 버튼이 계속 표시됩니다. "새로고침 후 시작"을 고르면 페이지의 첫 매니페스트·세그먼트 요청부터 기록합니다.
- **재생 상태**: video/audio 요소의 재생 경로(MSE / GeckoView 내장 HLS / 일반 파일), readyState·networkState, 버퍼(앞쪽 버퍼 초), 실제 재생된 시간, 해상도, 프레임 드롭, 미디어 오류 코드(네트워크·디코드·형식), `waiting`/`stalled` 이벤트를 기록합니다. Gecko가 디버그 정보를 제공하면 디코더 이름·하드웨어 가속 여부도 기록합니다.
- **EME/DRM 구분**: `MediaKeys` 사용과 `encrypted` 이벤트, 재생목록의 `EXT-X-KEY`/`EXT-X-SESSION-KEY`(METHOD, KEYFORMAT)를 읽어 평문 / 표준 AES-128 / SAMPLE-AES / DRM(FairPlay·Widevine·PlayReady)을 구분합니다. DRM이면 검증을 멈추며 해제하지 않습니다.
- **플레이어 네트워크**: 진단 중에는 플레이어의 요청을 성공·실패 모두 기록합니다(종류, 상태 코드, MIME, 호스트, Cookie/Referer 전송 여부). 기존 실패 보고서의 `observedPlayerMediaRequestCount`는 "미디어로 인식된 요청"만 셉니다. 그래서 0이어도 플레이어가 요청을 안 한 것은 아니며, 이제 보고서에 그 범위가 표시됩니다(`observedPlayerMediaRequestScope`).
- **단계별 검증**: 후보 탐지 / 매니페스트 검증 / 세그먼트 검증 / 브라우저 재생을 따로 표시합니다. 다운로드와 같은 요청 경로로 재생목록과 세그먼트를 최소한으로만 확인합니다.
- **차이 판정**: 플레이어가 받은 세그먼트와 다운로드 대상 재생목록의 세그먼트를 비교해 "같은 스트림인데 요청 맥락이 다름" / "다른 스트림" / "플레이어 요청이 관측 범위 밖"을 구분합니다.
- **실패 종류 구분**: HTML 보안 확인(챌린지) / 접근 권한 오류(401·403·로그인) / 일반 HTTP 오류(404·429·5xx) / 미디어 형식 오류(200이지만 HTML·비미디어)를 따로 보고합니다.
- **JSON 내보내기**: 결과 화면의 "JSON 내보내기"로 공유합니다. 주소·쿼리·쿠키·헤더 값·페이지 제목은 담지 않으며, 주소 대신 호스트와 이번 진단에서만 비교할 수 있는 해시 키를 씁니다. 내보내기 직전에 한 번 더 검사해 주소처럼 보이는 문자열은 모두 제거합니다.

### 서버 접근 제한 존중

- 진단 검증은 재생목록 1~2개, 세그먼트 최대 2개, AES 키 1개만 요청하며, 첫 거부(챌린지·403·429)에서 즉시 멈춥니다.
- **다운로드 수정 (실패 F-3d5b0023)**: 여러 세그먼트를 동시에 받을 때, 먼저 시도한 세그먼트가 호스트 차단을 확인한 뒤에도 순서를 기다리던 나머지 세그먼트가 같은 차단 요청을 다시 보냈습니다. 세그먼트 4개 기준으로 요청이 8번에서 2번으로 줄었습니다(회귀 테스트로 재현·확인). 이제 기다리던 세그먼트는 결과를 확인하고 바로 멈춥니다.

### GeckoView 공식 진단 기능과 한계

- `MediaSession.Delegate`(재생·일시정지·위치)와 콘텐츠 프로세스 충돌·종료 이벤트를 진단에 함께 기록합니다.
- 원격 디버깅(about:debugging)과 콘솔 로그(logcat)는 PC가 필요하고, 이 앱에서는 디버그 빌드에서만 켜집니다. 그래서 휴대폰만으로 쓸 수 있는 진단을 앱 안에 만들었습니다.
- GeckoView 160에는 m3u8을 video 요소에 직접 넣었을 때 쓰는 내장 HLS 플레이어(media3)가 있습니다. 이 플레이어의 요청이 확장 프로그램 webRequest에 보이는지는 실제 사이트에서 측정해야 합니다. 진단은 "재생은 됐는데 플레이어 요청이 0건"이면 이를 추정 결론으로 표시합니다.

> 실제 사이트의 원인은 이 진단을 기기에서 실행해 얻은 보고서로 확인해야 합니다. 이번 릴리스는 다운로드 경로의 쿠키·요청·재시도 로직을 바꾸지 않습니다(동시 세그먼트의 반복 차단 요청 제거만 포함). DRM 해제·보호 우회·사이트별 예외는 구현하지 않습니다. 기존 서명키 유지.
