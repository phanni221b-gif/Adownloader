## 변경 사항

### 실제 차단 지점이 "HTTP 200 HTML"로 잘못 보고되던 문제 수정 (공통 로직)

영상 주소가 같은 사이트의 중계 주소(리디렉션)인 경우, 앱은 먼저 **브라우저 세션이 있는 경로**로 요청하고 실패하면 **세션 없는 직접 연결**로 다시 시도합니다.

- 지금까지는 직접 연결이 **HTTP 200**만 받으면 성공으로 취급했습니다. 그런데 세션 없는 요청에 서버가 돌려주는 건 영상 목록(HLS)이 아니라 **일반 HTML 페이지**일 수 있습니다.
- 그 결과 실제 차단 지점(세션 경로가 리디렉션을 따라간 **CDN의 403**)이 보고서와 화면에서 사라지고, "HTTP 200 · 사이트 요청 차단"이라는 엉뚱한 원인이 표시됐습니다. 이후 요청도 세션 없는 경로로 고정됐습니다.
- 이제 직접 연결이 HTML을 받으면, 그 앞에서 세션 경로가 받은 **실제 거부(호스트·상태코드·리디렉션 단계)** 를 보고합니다. 세션 없는 경로로 고정하지도 않습니다. `DIRECT_HTML_DISCARDED` 진단 이벤트를 남깁니다.

이 수정은 **사이트별 예외가 아닌 공통 로직**이며, 진단을 바로잡을 뿐 **이 변경만으로 해당 사이트의 다운로드가 되는 것은 아닙니다**(CDN 403은 남아 있음).

> HTTP 403은 `ACCESS_BLOCKED`로 분류하며 DRM으로 단정하지 않습니다. DRM 해제·보호 우회·사이트별 예외는 구현하지 않습니다. 개인정보 보호 정책 그대로, 기존 서명키 유지.
