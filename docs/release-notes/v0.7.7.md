## 변경 사항

이번 버전은 **진단 정확도 수정**입니다. 특정 사이트에서 "브라우저로는 재생되는데 다운로드만 실패"하는 원인을 정확히 가려내기 위한 변경이며, 그 자체로 해당 다운로드를 성공시킨다고 보장하지는 않습니다(실패가 사이트의 접근 제한 때문인지, 앱 요청 구성 문제인지를 다음 실패 보고서에서 확실히 구분할 수 있게 합니다).

- **실패 단계 표기 정확화.** 인가 재생 세션 발급(핸드셰이크) 요청이 거부되면, 이전에는 "영상 조각 요청 · HTTP 403"처럼 **엉뚱한 단계로 표시**됐습니다. 이제 세션 발급 실패는 "영상 세션 요청", 실제 데이터 요청 실패는 "영상 데이터 요청"으로 **정확한 단계**를 표시합니다.
- **진단에 실제 전송 경로·단계 기록.** 실패 보고서(JSON)에 이제 ① 403이 **세션 발급 단계**인지 **리소스 요청 단계**인지(`RELAY_SESSION` 등), ② 그 요청이 **브라우저 네트워크(gecko)로 나갔는지 직접 연결(native)로 나갔는지**(`transport`)가 기록됩니다. 기존에는 `transport: UNKNOWN · httpStatus 0`으로만 남아 원인 추적이 불가능했습니다.
- **`geckoMediaSuccessObserved` 오해 방지.** 보호(세션 HLS) 후보는 구조상 "성공 네트워크 증거"를 기록하지 않으므로 이 값이 항상 false입니다. 이를 "브라우저도 재생 실패"로 **오해하지 않도록**, 보고서에 `candidateMediaProof`(observed / not-applicable / none) 항목을 추가해 "관찰 안 됨"과 "실제 실패"를 구분합니다.

> 개인정보 보호 정책은 그대로 유지됩니다(쿠키·인증 값·토큰·세션 비밀·응답 본문은 기록하지 않습니다). DRM 해제·보호 우회·비인가 키 추출·접근 제한 우회는 구현하지 않습니다.
