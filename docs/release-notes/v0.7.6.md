## 변경 사항

- **브라우저에서는 재생되는데 다운로드만 "사이트 요청 차단"으로 막히던 세션 HLS 문제 수정.** 로그인하지 않았는데도 일부 사이트는 재생 중에 **HttpOnly 접근 쿠키**(브라우저만 보관하고 자바스크립트로는 읽을 수 없는 쿠키)를 발급해 영상 요청을 거르는 경우가 있습니다. 인가 재생 세션만 유독 **브라우저 네트워크가 아니라 앱의 독립 연결**로 요청을 보내고 있어서, 이 쿠키(그리고 재생이 사용한 TLS/HTTP2)를 그대로 쓰지 못해 403으로 거부당했습니다. 그래서 브라우저에서는 재생되는 영상이 다운로드만 막혔습니다(v0.7.5의 로그인 쿠키 전달만으로는 HttpOnly 쿠키를 가져올 수 없어 해결되지 않았습니다).
- **수정 방식.** 인가 재생 세션 요청을 **일반 HLS/DASH 다운로드와 똑같이 브라우저 네트워크(Gecko)로** 보냅니다. 이렇게 하면 재생이 쓰던 것과 **동일한 쿠키 저장소(HttpOnly·재생 중 갱신된 쿠키 포함)와 TLS/HTTP2**를 그대로 사용합니다. 브라우저 네트워크가 없는 상황에서는 기존의 직접 연결 방식으로 자동 대체됩니다.
- **진단 정확화.** 세션/리소스 요청이 거부되면 이제 **실제 HTTP 상태 코드와 막힌 단계(세션 핸드셰이크 / 리소스 받기)**를 진단에 기록합니다. 이전에는 이 경우가 `httpStatus 0 · transport UNKNOWN`으로만 남아 원인을 알기 어려웠습니다.

> 이것은 **사용자 본인의 인증 접근**이며 보호 우회가 아닙니다. 앱은 여전히 자체 EC 키쌍을 만들어 사이트가 공개적으로 제공하는 ECDH 핸드셰이크로 세션을 직접 생성하고, 자체 재생 세션으로 리소스를 받습니다. 브라우저 키나 DRM 비밀은 가져오지 않으며, DRM 해제·보호 우회·비인가 키 추출은 구현하지 않습니다.
