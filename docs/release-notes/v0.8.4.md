## 변경 사항

### 세그먼트 다운로드 대체 경로 추가 (루트 #1)

영상 조각(세그먼트)이 담긴 호스트가 **일반 네트워크로는 전부 막히는**(직접 연결·브라우저 네트워크 모두 403) 경우, 마지막 수단으로 **지금 재생 중인 탭의 페이지 맥락(content-script fetch)** 으로 그 조각을 가져옵니다. 매니페스트 부트스트랩이 이미 쓰던 그 경로와 동일합니다.

- **특정 사이트 전용 예외가 아닙니다.** 모든 사이트에 똑같이 적용되는 범용 대체 경로입니다.
- **보호 우회가 아닙니다.** 그 탭이 **실제로 이미 불러온** 조각만, 페이지 자신의 fetch로 가져옵니다. 탭이 요청한 적 없는 조각은 이 경로로도 받지 않습니다.
- **조건:** 조각 전체를 받는 요청에만 적용됩니다(바이트 범위·이어받기 요청은 메모리 본문으로 서빙할 수 없어 제외). 한 조각당 8 MiB 상한.
- **낭비 방지:** 한 호스트가 이 경로로 한 번 성공하면, 그 호스트의 남은 조각은 막힌 네트워크 시도 두 번을 건너뛰고 바로 이 경로로 갑니다. 이 경로까지 막히면 그 호스트는 "차단"으로 표시해 남은 조각이 빠르게 실패합니다(반복 요청 폭주 방지).
- `transport: content-script` / `action: SEGMENT_CONTENT_SCRIPT`(성공·시도) / `SEGMENT_CONTENT_SCRIPT_BLOCKED`(실패)로 진단에 기록됩니다.

> 이 경로가 통하는지는 사이트의 보호 방식에 따라 다릅니다. 매 요청 JS 챌린지나 CORS로 페이지 fetch 읽기를 막는 사이트에서는 통하지 않을 수 있으며, 그 경우 솔직하게 실패로 보고합니다. DRM 해제·보호 우회·비인가 키 추출은 구현하지 않습니다.

### 진단 품질 개선 (0.8.3에서 통합)

- **진단 용어 정리.** 브라우저 네트워크(GeckoWebExecutor) 요청이 이전엔 `transport: native` / `NATIVE_INITIAL`로 잘못 기록됐습니다. 이제 `transport: gecko` / `action: BROWSER_INITIAL` / `requestType: browser-fetch`로, 페이지 컨텐츠 스크립트 요청(`content-script` / `content-script-fetch`)과도 구분해 기록합니다.
- **실패 사유 구체화.** 포괄적인 `DOWNLOAD_FAILURE` 대신, 서버의 의도적 접근 제한(`ACCESS_BLOCKED`·`AUTH_REQUIRED`·`URL_EXPIRED`·`DRM_PROTECTED`)과 엔진 측 한계(`STREAM_UNSUPPORTED`·`MANIFEST_INVALID`), 일시적 오류(`NETWORK_ERROR`·`SERVER_ERROR`)를 구분해 기록합니다.
- **재생 감지 값 명확화.** `geckoMediaSuccessObserved`는 "브라우저 재생 성공"이 아니라 "후보에 연결된 성공 네트워크 응답을 포착했는지"입니다. DOM/보호 응답 감지는 구조상 이 값을 만들지 않으므로, `candidateMediaProof`(observed / not-applicable / none)를 추가해 "관찰 안 됨(구조적)"과 "실제 실패"를 구분합니다.
- **실패 기록의 시작 보존.** 이벤트 기록이 길어져도 **처음 16개 + 최근 50개**를 유지합니다. 이전엔 앞부분이 잘려 최초 실패 과정(전송 방식 결정 등)을 볼 수 없었습니다.
- **차단 페이지 분류 보강.** HTML 차단/챌린지 페이지 판별에 `forbidden`·`ddos`·`차단` 등을 추가해 정확도를 높였습니다.

> 개인정보 보호 정책(쿠키·인증 값·응답 본문 미기록) 그대로, 기존 서명키 유지.
