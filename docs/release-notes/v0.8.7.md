## 변경 사항

"재생 네트워크가 webRequest를 통과하지 않는다 / 앱 결함 없다"는 결론을 **독립적으로 재검증**하기 위한 작업입니다. 이전 결론 중 일부는 검증됐고 일부는 가설이었음을 인정하고, 그 간극을 메웁니다. 다운로드 전송 로직은 바꾸지 않았습니다.

### 1) 실제 GeckoView 통합 테스트로 관찰 경로 검증 (모의 테스트 아님)

- 지난 `ci/test-media-observation.cjs`는 **모의 이벤트 단위 테스트**(JS 로직만 검증)였습니다. 이번에 **실제 GeckoView**에서 동작을 검증하는 통합 테스트 `PlayerMediaObservationIntegrationTest`를 추가했습니다: 실제 페이지가 **200 미디어 세그먼트**와 **403 미디어 세그먼트**를 fetch하면, 각각 그 호스트가 성공/실패로 기록되는지 에뮬레이터에서 확인합니다.
- 이로써 "관찰 기능이 실기기에서 실제로 작동한다"가 모의가 아닌 실제 실행으로 입증됩니다. 따라서 실제 사이트에서 기록이 비어 있다면, 그건 파이프라인 고장이 아니라 **플레이어가 관찰 가능한 미디어 요청을 하지 않았다**는 뜻으로 좁혀집니다.

### 2) 진단 보고서의 모호함 제거

- `observedPlayerMediaRequestCount`를 **항상** 기록합니다. 값이 **0이면** 관찰된 플레이어 미디어 요청이 정말로 0건(서버 차단도, 후보 불일치도 아님), 값이 **양수인데 호스트 목록이 비어 있으면** 관찰은 됐으나 호스트 표기가 필터된 것 — 이 둘을 명확히 구분합니다(직렬화·필터 아티팩트 배제).

### 3) 개발용 원격 디버깅 (디버그 빌드 전용)

- 디버그 빌드에서만 GeckoView 원격 디버깅(`remoteDebuggingEnabled`)을 켭니다. Firefox 개발자도구(about:debugging)로 **확장과 무관하게 실제 재생 네트워크를 직접 관찰**할 수 있어, "관찰 불가한 재생 파이프라인"인지 "놓친 관찰"인지 독립적으로 확인할 수 있습니다. **정식 릴리스(이 APK)에서는 꺼져 있습니다**(`BuildConfig.DEBUG=false`).

> 이 변경들은 **검증·진단**을 위한 것이며 다운로드 성공을 보장하지 않습니다. HTTP 403은 그대로 `ACCESS_BLOCKED`(DRM 아님). DRM 해제·보호 우회·비인가 키 추출·특정 사이트 전용 예외는 구현하지 않습니다. 개인정보 보호 정책(쿠키·인증 값·응답 본문·URL 미기록) 그대로, 기존 서명키 유지.
