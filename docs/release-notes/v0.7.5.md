## 변경 사항

- **로그인이 필요한 영상(예: `/premium/` 페이지)의 세션 HLS 다운로드 실패 수정.** 로그인한 상태로 브라우저에서 재생되는 영상을 받으려 할 때, 다운로드가 "사이트 요청 차단"(ACCESS_BLOCKED)으로 ROOT_MANIFEST 단계에서 멈추는 문제가 있었습니다. 원인은 인가 재생 세션을 만드는 과정에서 **사용자 본인의 로그인 쿠키를 함께 보내지 않았기** 때문입니다(기존에는 user-agent·origin·referer·accept-language 네 개만 전달). 로그인 게이트가 있는 사이트는 로그인 쿠키가 없는 요청을 403으로 거부하므로, 브라우저에서는 재생되는데 다운로드만 막혔습니다. 같은 사이트의 로그인 불필요 영상(2.2GB 세션 HLS)은 정상 완료되던 것과 대비되는 증거입니다.
- **수정 방식.** 일반 HLS/DASH 전송이 이미 하는 것과 똑같이, 해당 미디어 주소에 대해 **브라우저가 보낸 사용자 본인의 요청 맥락(Cookie·Authorization·x-\* 세션 헤더)을 같은 출처(origin)로만** 전달합니다. 모든 세션 요청은 루트 주소의 출처로만 나가도록 제한되어 있어, 쿠키가 다른 곳으로 새지 않습니다.

> 이것은 **사용자 본인의 인증 접근**이며 보호 우회가 아닙니다. 앱은 여전히 자체 EC 키쌍을 만들어 사이트가 공개적으로 제공하는 ECDH 핸드셰이크로 세션을 직접 생성하고, 리소스는 앱이 발급받은 자체 재생 세션으로 받습니다. 브라우저 키나 DRM 비밀은 가져오지 않습니다. DRM 해제, 보호 우회, 비인가 키 추출은 구현하지 않습니다.
