## 변경 사항

### 브라우저 세션과 다운로드 요청의 맥락 일치 (공통 로직)

비교 분석한 WebView 기반 다운로더는 **모든 요청과 리디렉션 단계마다 브라우저 쿠키 저장소에서 그 주소의 쿠키를 다시 조회**해 붙입니다. Adownloader의 직접 연결은 원본 주소에서 관찰한 쿠키와 다운로드 중 받은 `Set-Cookie`만 썼기 때문에, 화면(DOM)에서 찾은 영상이나 리디렉션으로 넘어간 CDN 호스트에는 브라우저가 가진 세션 쿠키가 전달되지 않았습니다(`cookiePresent: false`).

- 확장 프로그램 백그라운드에 **쿠키 조회 브리지**를 추가했습니다. 직접 연결은 요청 주소마다 Gecko 쿠키 저장소에 그 주소의 쿠키만 물어봅니다(도메인·경로·Secure·만료·페이지 기준 분할 저장소는 브라우저가 판단).
- 다른 사이트(크로스 사이트) 요청에는 그 페이지 기준으로 분할 저장된 쿠키와 `SameSite=None` 쿠키만 보냅니다. 사이트 쿠키가 CDN 호스트로 넘어가지 않습니다.
- 우선순위: 관찰된 요청 쿠키 < 실시간 브라우저 쿠키 < 이 작업이 받은 `Set-Cookie`. 브라우저 쿠키는 작업 저장소·진단 기록에 저장하지 않습니다.
- 관찰된 Referer가 없을 때 브라우저 기본 정책(strict-origin-when-cross-origin)대로 보냅니다: 같은 출처는 페이지 전체 주소, 다른 출처는 페이지 출처만, HTTPS→HTTP는 보내지 않음.

### HTTP 200이어도 HTML이면 영상 조각으로 저장하지 않음

- 세그먼트·키 응답 본문이 HTML 문서이면 상태 코드와 관계없이 거부하고 `SEGMENT_BODY` 단계, 받은 종류(일반 페이지/보호 페이지/로그인)로 분류합니다. 재시도 폭주 없이 한 번에 실패합니다.

### 재시도·이어받기 안정성

- 일시 오류(연결 실패, 408, 429, 5xx)만 재시도하고, `Retry-After`를 따르며(최대 30초), 그 외에는 지터가 있는 지수 대기 후 최대 4회 시도합니다. 401/403/404 등은 재시도하지 않습니다.
- 암호화되지 않은 세그먼트가 중간에 끊기면 이미 받은 바이트부터 `Range`로 이어받습니다. 서버가 범위를 정확히 지키지 않으면 이어 붙이지 않고 처음부터 다시 받습니다.

### 실제로 재생에 성공한 영상 주소를 먼저 표시

- 브라우저가 성공 응답과 매니페스트 본문을 확인한 후보를 목록 맨 앞에 둡니다. 확인되지 않은 화면 힌트(`dom-media` 등)도 그대로 목록에 남습니다.

> 실제 yasadong 사이트 다운로드는 기기에서 검증되지 않았습니다. 같은 실패 패턴(세션 없으면 HTML 200, 리디렉션 후 CDN 403)은 모의 서버 회귀 테스트로 재현·검증했습니다. DRM 해제·보호 우회·사이트별 예외는 구현하지 않습니다. 개인정보 보호 정책 그대로, 기존 서명키 유지.
