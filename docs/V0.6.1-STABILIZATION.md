# Adownloader 0.6.1 / versionCode 11

Scope: five targeted stability improvements on the accepted 0.6.0 architecture. Java/Gecko-only browser, five isolated tabs, original-quality sample-copy mux, encrypted minimal request context, direct/HLS/DASH continuation, UIDT/FGS, existing icon and fixed release certificate remain.

1. **Space / durable finalization.** Estimate known segment ranges or bitrate-duration, subtract committed bytes, allow output overhead and safety. Reject predictable shortage before payload downloads. After final native validation and fsync, commit full final length/SHA-256 to schema 2, then purge source files. Resume from that descriptor after force-stop, including expired sources. Original segment hashes remain. Interrupted pre-commit output never authorizes deletion. STORAGE_FULL remains separate. Native MP4 mux still needs source plus output at peak; this release does not promise 20 GB output in 20 GB free space. Unknown-length lower bounds do not guarantee enough capacity.
2. **Access classification.** Default 401/403 to AUTH. Only 403 with signed-URL evidence plus a prior successful transfer/known expired timestamp, without WWW-Authenticate, becomes EXPIRED_URL. Both retain NEEDS_REFRESH; distinct messages and original-page navigation are available. No server-side cause is claimed with certainty.
3. **CDN identities.** AWS signing whitelist, CloudFront canned/custom scoped policies, explicit signature+epoch pairs, Akamai ACL-preserving tokens, JWT signature-only normalization. Preserve resource/quality IDs, unknown parameters and JWT header/payload. Generic ambiguous endpoints/duplicate keys remain separate. The newest exact URL retains its own context. Request URLs are never rewritten. Compatible-plan refresh uses the same policy and still checks representations, ranges and sequence.
4. **Single download authority.** Remove legacy DownloadHistory state/progress writers and preferences observer. SQLite drives records. Preserve v0.5 import in a transaction and remove legacy payload only after commit. Completed MediaStore references survive. UI-only settings are unaffected.
5. **Schema evolution.** Explicit version 2 and sequential migration dispatcher; retain jobs/parts/history/context encryption. Roll back failed upgrades, reject downgrade without destructive reset, log sanitized version errors.

## Added verification

- CdnQueryPolicyTest: canned/custom CloudFront, AWS, generic sig/exp/hmac, semantic IDs/quality, ambiguous/duplicate parameters, Akamai ACLs, JWT payloads, latest full URL/context.
- AccessFailureTest: default access errors, explicit expiry, previous-success evidence, authentication challenges and conservative 401.
- StorageBudgetTest: synthetic 20 GiB estimates, resumed capacity, unknown lengths and overflow.
- RefreshPlanMatcherTest: CDN signature rotation reuses compatible plans; different IDs/JWT payloads do not.
- SchemaMigrationIntegrationTest: real v1 fixture with completed history, segment journal and both encrypted context forms; v2 feature use; rollback on injected conflict; explicit downgrade rejection.
- FinalizedStorageIntegrationTest: pre-commit interruption retains sources; validated commit deletes them; reopen/recovery works without network; corrupt output is rejected; impossible capacity and typed ENOSPC are distinguished; actual transfer writes no duplicate legacy state.
- ProcessRecoveryTest + external adb harness: prepare final output, real force-stop, expire source URLs, reopen/resume, complete with zero additional media requests. Existing direct/HLS/DASH and UI controls remain in the harness unchanged.

## Limits

Android 36 x86_64 emulator evidence is not Galaxy Fold8 hardware validation. No physical Fold8 was available. No DRM bypass, live recording, HLS gap/discontinuity support, DASH multi-period, or transcoding is introduced. Platform codec/demux/mux limits remain. Signed identity rules deliberately prefer duplicate candidates over merging uncertain resources; JWTs with changed payloads may remain separate. System filtering remains external (Unicorn Pro/NordVPN).
