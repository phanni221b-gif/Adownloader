# Adownloader v0.6.2 검증 기록

## 변경 내용

- Gecko 브라우저와 다운로드 엔진의 분리를 유지했다. Android WebView, 광고/계정/클라우드 SDK를 추가하지 않았다.
- 비DRM HLS/DASH의 실제 네트워크 응답을 우선하며, blob은 재생 신호로만 취급한다. TS/m4s/cmfv/cmfa/init 조각은 개별 다운로드 후보로 등록하지 않는다.
- MSE/재생/연속 조각 신호가 있는 프레임에서 10초 동안 제한적으로 조사한다. 동시에 최대 4개 응답, 프레임당 최대 8개, 각 응답의 앞 8KiB만 확인하고 원래 바이트를 그대로 전달한다. 텍스트 HLS/MPD 서명으로 확장자 없는 실제 manifest를 찾는다. 페이지 fetch/XHR를 덮어쓰는 코드는 없다.
- 이미지·스크립트·일반 문서 응답은 스트림 조사 때문에 대기하지 않는다. 미디어 가능 요청에만 Cookie/Referer/Origin/User-Agent의 제한된 임시 컨텍스트를 보관하며, 그 외 요청의 Cookie를 맵에 보관하지 않는다. 실패 응답은 다운로드 후보가 아니다.
- 작업별 HTTP Cookie jar는 root/redirect/variant/key/segment의 Set-Cookie를 이어받는다. Domain/Path/Secure/SameSite 및 공개·사설 suffix 경계를 적용한다. 초기 실제 요청 Cookie는 원래 origin에 제한하고, 관찰한 조각 Cookie는 해당 URL에만 전달한다. 브라우저 Cookie jar 전체를 읽지 않는다.
- 필요한 응답 Cookie와 요청 컨텍스트는 기존 Android Keystore AES-GCM 암호화 journal 안에만 저장한다. 작업 간 jar를 공유하거나 프로세스 전역 CookieHandler를 변경하지 않는다. 쿠키 삭제 및 재시작 후 복원도 검사한다.
- BOM/CRLF/주석, 동일한 반복 EXT-X-MAP, DISCONTINUITY-SEQUENCE, 미디어 BYTERANGE의 생략 offset, query-only URI, 오디오 그룹, AES-128 identity를 처리한다. DRM/SAMPLE-AES, live, gap, 실제 불연속, 바뀐 초기화 트랙, delta HLS, 다중 Period DASH는 완료로 처리하지 않는다.
- HTTP 200 HTML challenge/login을 깨진 manifest와 구분한다. 진단에는 host/status/MIME/redirect 수/단계/태그/category만 남긴다. 본문·URL path/query·Cookie·토큰·헤더 값은 넣지 않는다.
- 제목은 og:title, twitter:title, 본문 h1, document.title 순서로 선택하고 확실한 사이트 suffix만 제거한다. Sheet가 열린 뒤 바뀐 제목도 갱신한다. 파일명은 의미 있는 Content-Disposition, 게시글 제목, mediaTitle, 의미 있는 URL, 시각 순서이며 충돌 회피/문자 정리는 유지한다.
- 최근 앱에서 작업을 제거해도 활성/대기 다운로드를 정지시키지 않는다. Activity와 Gecko 세션/바인딩은 닫고, 디스크에는 URL/제목/선택 탭/데스크톱 모드만 남겨 새 세션으로 다시 요청한다. Android 강제 종료는 별개이며 자동 진행 중으로 표시하지 않는다.
- 후처리는 기존 MediaExtractor/MediaMuxer의 무손실 remux만 사용한다. FFmpeg는 CI 합성 테스트 파일 생성에만 쓰고 앱에 포함하지 않는다.

## 재현 및 검증 범위

변경 전 실제 v0.6.1 확장 코드를 고정한 합성 테스트에서 Blob/MSE 신호와 확장자 없는 text/plain HLS의 후보 수가 0임을 재현했다. 변경 후 실제 manifest 후보와 원본 바이트 전달, 조각/실패 응답 제외, 필터 상한·타임아웃, 탭/프레임 제목 분리 및 API 부재 fallback을 검사한다.

HLS 수정 전 반복 MAP/주석-BOM/redirect Cookie의 세 회귀 테스트가 실제 실패했고 수정 후 통과했다. 기존 테스트는 유지했으며 인증 fixture에는 새 제목 우선순위에 맞게 명시적인 og:title을 추가했다. Android JSON의 slash escaping은 문자열 비교 대신 URL key를 디코딩해 검증한다.

Android 통합 테스트는 실제 Gecko + 로컬 HTTP 서버로 확장자 없는 HLS TS/fMP4와 DASH를 찾아 계획·저장하고, 최종 파일의 duration 및 영상/음성 트랙을 확인한다. 작업 제거와 실제 adb force-stop은 별도 외부 harness로 검증한다. 응답 Cookie 복원 시 root 재요청 없이 기존 조각을 이어받는지도 검사한다.

로컬 기본 테스트 87개, 확장 스크립트 검증 세 묶음, release lint 및 Android 테스트 APK 컴파일을 수행했다. 최종 CI 결과/서명/APK 정보는 정식 릴리즈 검증 자료에 기록한다.

## 성능 측정 해석

같은 합성 페이지(200 SVG 요청 + DOM 변경 + 늦게 추가되는 영상)를 실제 Gecko에서 탐색하고 DCL/load, 전체 요청 수, onBeforeSendHeaders 호출/누적 경과시간, 맵 최대 크기/정리 방문 횟수, DOM/Performance 처리 및 event-loop 지연을 기록한다.

기준 확장 코드의 전체 문서 스캔 수와 수정 코드의 하위 노드 스캔 호출 수는 의미가 달라 직접 비교하지 않는다. 수정 코드에는 별도의 domFullScans를 기록한다. 리소스 재처리와 맵 정리 비용을 줄였다는 결과를 전체 실사이트 로딩 속도 향상으로 확대하지 않는다. DCL/load와 지연은 에뮬레이터 단일 실행의 편차가 크므로 원자료와 함께 보고한다.

## 실사이트 및 기기 제한

제공받은 첫 사이트는 이 환경의 HTTP 확인에서 HTML 안내/접근 제한 응답을 반환했고, 두 번째 사이트에서도 재생 가능한 manifest를 확보하지 못했다. 이를 Fold8 실패의 확정 원인이라고 단정하지 않는다. 실제 사이트 호환성 수정 완료나 재생/다운로드 성공을 주장하지 않는다. 두 사이트의 원본 URL/본문/미디어 경로/토큰은 공개 CI나 fixture에 넣지 않았다.

실제 Galaxy Fold8은 연결되어 있지 않다. Android 36 x86_64 에뮬레이터의 통합 검증과 ARM64 릴리즈 구조/서명 검증을 구분한다. 시스템이 Gecko 네이티브 메모리를 언제 회수하는지까지 보장하지 않는다. 앱 소유 세션/뷰/메시지 delegate 해제와 재실행의 새 세션/URL 재요청을 검사한다.

DRM 우회는 구현하지 않는다. 네트워크 차단/challenge/만료 URL은 합법적인 접근 또는 새 주소가 필요할 수 있다.
